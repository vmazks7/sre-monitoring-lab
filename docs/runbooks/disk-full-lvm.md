# Runbook: Disk Full / LVM Resize

**Когда открывать:** `df -h` показывает Use% выше 90% на любой из ВМ,
либо сервис отказывается стартовать с ошибками, ссылающимися на диск
(Elasticsearch — `disk watermark`, PostgreSQL — `could not write to file`,
любой сервис — `No space left on device`).
**Приоритет:** P1 — заполненный диск обычно вызывает каскад отказов, 
не единичную проблему.

## Диагностика

### Где именно кончилось место

```bash
df -h
```
Смотри не только `/`, но и отдельные точки монтирования (`/boot`,
`/var` — если он вынесен отдельно, что в этой лабе не так, но полезно
перепроверять на других системах).

### Что реально занимает место

```bash
sudo du -sh /var/lib/elasticsearch /var/log/* /var/lib/postgresql/* 2>/dev/null | sort -rh | head -20
```

Частые виновники в стеке этого проекта:
- `/var/lib/elasticsearch` — сами данные индексов, растёт с объёмом логов
- `/var/log/journal` — systemd journal может расти без ограничения по
  умолчанию на некоторых конфигурациях
- WAL-файлы PostgreSQL при интенсивной записи транзакций
  (`/var/lib/postgresql/18/main/pg_wal`)

## Быстрая временная мера — почистить, не расширяя диск

Если нужно немедленно освободить немного места, не дожидаясь расширения
диска:
```bash
sudo apt clean
sudo journalctl --vacuum-time=2d
```
Это временная мера, не решение.

## Настоящее решение — расширение диска (LVM)

Актуально, если диск ВМ уже увеличен в VMware (Edit VM Settings → Hard
Disk → увеличить размер), но ОС ещё не знает об этом.

### 1. Проверь текущую картину

```bash
lsblk
```
Смотри на разницу между размером самого диска (`sda`) и размером
раздела LVM (`sda3` или похожий) — если диск больше раздела, есть
неиспользуемое пространство.

Если ядро не видит новый размер диска сразу после увеличения в VMware:
```bash
echo 1 | sudo tee /sys/class/block/sda/device/rescan
lsblk
```

### 2. Расширь раздел до полного размера диска

```bash
sudo growpart /dev/sda 3
```
(номер раздела — по факту из `lsblk`, не всегда `3`; если ответ
`NOCHANGE` — раздел уже занимает всё доступное место, следующий шаг всё
равно может понадобиться отдельно, если раздел расширялся ранее без
LVM-шагов)

Если `growpart` не установлен:
```bash
sudo apt install -y cloud-guest-utils
```

### 3. Расширь physical volume и logical volume

```bash
sudo pvresize /dev/sda3
sudo lvextend -l +100%FREE /dev/mapper/ubuntu--vg-ubuntu--lv
```
(точное имя `/dev/mapper/...` — из вывода `lsblk`, обычно
`ubuntu--vg-ubuntu--lv`, но подтверди)

### 4. Расширь файловую систему

```bash
sudo resize2fs /dev/mapper/ubuntu--vg-ubuntu--lv
df -h /
```

## После расширения — сервисы с блокировкой по диску не восстанавливаются

Elasticsearch пересчитывает allocation автоматически, если статус остаётся `red` дольше пары минут:
```bash
curl -X POST "http://10.10.10.13:9200/_cluster/reroute?retry_failed=true"
```
Подробнее — `elasticsearch-cluster-red.md`.
